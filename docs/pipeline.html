HBL Account Opening Form · extraction pipeline

How one scanned page becomes checked data

A page enters as pixels and leaves as a list of named, format-checked values. Between those two points sit nine decision gates — each one deciding whether the page is usable, whether a box holds ink, whether a reading can be trusted, and whether a human needs to look. This is the whole path, gates included.

Why the ink is measured before anything is read

Two of the nine gates depend on a single number: how much pen ink a box owns. It is worth seeing how that number is produced, because it is what lets the pipeline tell the model things instead of asking it.

Stage by stage

Each stage below narrows what the next one has to decide. The ordering is the pipeline's, not an outline — stage 4 cannot run before stage 1 has put the page into template space.

01

Put the scan into template space

src/register.py

The blank template is a vector PDF, so its geometry is exact. Feature points are matched between template and scan and a homography warps the scan onto it, correcting rotation, scale, translation and mild perspective at once. After this, template point (x, y) is always at the same pixel of the scan.

Page order is verified rather than assumed: the expected page is tried first, and only if it fails is the full search run. Scoring by raw descriptor matches does not work — it once assigned scan page 2 to template page 6 — so candidates are scored by RANSAC-verified inliers.

Gate — page quality coverage ≥ 0.80 and offset ≤ 4 px. A misaligned page does not give slightly wrong data, it reads ink from the wrong boxes. Failing does not stop the run — every field on that page carries the page's problems into the review list.
02

Decide which strokes belong to which field

src/fields.py

Handwriting on this form overflows badly — up to 34 pt against 16 pt row spacing, with 23.5% of all ink sitting wholly outside every box. So a field's extent is measured from the ink, not assumed from the rectangle: every pixel is assigned to its nearest box, ink must start within 8 pt of a box to be claimed at all, and once a stroke is claimed the rest of its connected component comes with it.

Gate — is there anything here ink_px == 0 → the field is settled as empty and never costs a model call. 60 of this form's 247 answer boxes exit here.
03

Read the tick boxes without a model

src/read_checkboxes.py

Roughly 45% of all fields are checkboxes, and they can be read deterministically. Ink is measured inside each box, then each question is resolved competitively: most ink wins, provided it holds at least 55% of the group's total. That is what survives ticks drawn far larger than the 11 pt box, spilling across their neighbours.

Gate — one answer or many Questions the form itself words as "select all that apply" skip the competition and are scored independently.
04

Read the whole page in one call

src/read_page.py · src/prompts.py

The page is trimmed to the region holding fields, scaled to a pixel budget, and every answer box gets a thin outline and a numbered tag — placed in the printed-label column, where covering something costs nothing. The prompt is the matching numbered list: each entry names the field, states the exact Pakistani or HBL format expected, and carries the ink verdict from stage 2.

Because of that pairing, the model is never asked which value belongs to which label — the failure that whole-page OCR is known for. It is asked only to read handwriting.

Gate — did the reply survive The request carries a JSON schema requiring keys 1..N, so a short reply is impossible. If it still fails to parse, those fields are recorded as unread rather than guessed at.
05

Check every number a second time

src/read_page.py · _sweep_structured

At a page resolution cheap enough to be practical, digits suffer — and a wrong digit produces a valid value that no rule can catch. So every CNIC, date, phone, IBAN, postcode and account number is read again from its own crop by a small OCR model, which has no vocabulary to guess with and simply copies characters.

Gate — who is believed The OCR reading wins only if it is well formed, and never replaces a real value with a blank. If both readings are valid and they differ, the OCR value is taken and the field is flagged — nothing downstream can settle that disagreement.
06

Re-read what cannot be right

src/read_page.py · _retry_page

A field is re-read from an enlarged crop, with neighbouring strokes painted out, when it fails its format check, or when its value contradicts the ink measurement in either direction — a box holding 7,961 px of pen that came back empty, or a box holding 186 px of a neighbour's bleed that came back with a value.

Gate — accept the second reading? Only if it is well formed. A valid value is never traded for an invalid one just because it arrived later.
07

Judge every value, and say why

src/validate.py · src/extract.py

The field's label decides its type, and the type decides both what the model was told to expect and what the value is now checked against — one source, so the two cannot drift apart. The rules are the Pakistani formats as issued: a CNIC's first digit is the issuing province and is never 0; Karachi and Lahore landlines carry 8-digit subscriber numbers and everywhere else 7; an IBAN on this form must carry HBL's own bank code.

Repairs are one-directional — a letter→digit substitution is accepted only when it turns an invalid value into a valid one — and every change is recorded in the record's note. Nothing is silently corrected and nothing is silently dropped.

Gate — does a human need to see it A field is flagged when it fails its format, when two readers disagreed, when the ink contradicts it, or when it sits on a badly registered page.

The thread running through all of it: the blank template already knows where every field is and what it should contain. So the model is only ever asked to read handwriting — never to work out layout, never to judge whether a box is empty, never to decide which value belongs to which label.

Every time one of those judgements was left to the model, it got it wrong: two phone numbers returned under each other's labels, a ticked option copied into the blank box beside it, a passport number in plain view reported as empty.
